## Grok behavior

Keep the fork's default-on hourly stable CLI-version sync, trusted official metadata sources, compare-and-set persistence, no downgrade, and exact 426 one-time replay only after version advancement. The official static-version policy would regress these capabilities, so only its compatible request identity is adopted.

Quota decisions now distinguish an observed upstream retry boundary from a local probe interval. A fresh 45-second Retry-After cannot be inflated to 30 minutes by historical adaptive backoff; an expired observed window cannot re-arm cooldown; free-quota bodies without reset headers use the existing 10-minute probe interval consistently across HTTP status codes. Model-specific quota and request-policy refusals retain their separate scopes. Successful concurrent recovery still uses generation-aware clearing.

Terminal Grok string-valued errors retain a bounded, credential-redacted diagnostic in Ops while preserving the existing raw-body logging toggle and client-status policy. Invalid input and content-policy refusals remain request failures and must not quarantine the account pool.

Operational entitlement verification additionally identified stale Heavy labels. The operator requested Heavy-only scheduling: only currently verified Heavy accounts remain enabled; existing manually paused accounts stay paused. A successful inference is not proof of a paid subscription. Inventory changes and private account lists are archived outside the public repository. New accounts require entitlement verification before enabling; this release does not introduce a periodic account-tier automation.

## Preserved invariants

Existing durable billing, deleted-key settlement, video/WS safeguards, CommandCode Go relay/UI, and request-policy/quota separation are preserved. All 311 pre-existing migration files retain their bytes. The two new SQL migrations add a default-zero payment bonus column and expand platform constraints with TypeSafe; they are compatible with the previous binary while both versions serve requests. New promotion configuration remains opt-in.

Rolling startup no longer removes concurrency slots just because they carry another process's prefix: that process may still be serving customers. Existing expiration checks and periodic TTL cleanup reclaim stale slots. Disconnected chat response drains keep reading authoritative usage for up to five minutes, then close a never-ending upstream body even if it keeps sending heartbeats. Connected requests have no added lifetime limit, known partial usage remains billable, and no token count is invented. Image cancellation and durable video settlement remain unchanged.

Redis password-reset values now contain hashes. Reset emails issued by g2 shortly before deployment may need to be requested again; normal users/passwords and login sessions are unchanged. Existing anonymous verification rate limiting fails open if Redis is unavailable, matching the selected upstream policy.

## Validation and release procedure

The full backend and frontend suites, focused race checks, actual PostgreSQL migration/settlement cases and release failure tests cover the changed behavior. The private project journal holds exact results; skipped database cases are never counted as successful integration tests.

Production availability is a prerequisite for deployment. Build and verify a separate candidate with isolated logs/configuration, shared database/Redis and shared page assets. Apply only audited additive migrations in a transaction with short lock and statement deadlines. Validate the candidate and real canary before moving Getoken's internal upstream URLs and gracefully reloading the public Caddy route. Both versions remain running during the switch; any switch failure restores the original routes without restarting Getoken. Retire the old instance only after traffic has moved and its active work is reconciled. A process exit code alone cannot pass the application drain gate.

The former stop-first release produced a service gap while an abandoned upstream stream failed to drain. That procedure is retired. Runtime image construction now flattens the existing trusted OS filesystem, replaces only the verified binary, and retains its entrypoint and environment, avoiding the accumulation of historical binary layers. No package download or unrelated service restart is part of promotion. Preserve current and known rollback artifacts; cleanup is scoped and never uses global volume/cache pruning.

Paid CommandCode Go inference still awaits the operator's subscription. Historical upstream errors and an earlier unresolved request without authoritative usage must not be described as fully recovered billing or a permanent error-free guarantee.
